# Decision — M006 Save/Load v1 contract (2026-10-08)

No architecture rewrite. Narrow, reasoned resolutions:

- File layer: envelope {schema, content, sha256, snapshot} + atomic
  temp-write/fsync/rename + rotation (live + .bak1 + .bak2) + newest-valid-wins
  load with per-file reasons. Single-process local game: last-writer-wins, no
  locking (documented, not built).
- Versions: SCHEMA_VERSION/CONTENT_VERSION = 1. Older → ordered migrations
  (v0 fixture proves the mechanism; migrations add shape, never gameplay
  values). Newer → loud refusal. Content mismatch → loads with a returned flag.
- Checksum over the canonical snapshot string; any mismatch = corrupt file.
- Stance labels stay stored as hysteresis anchors (narrow deviation from §10.1,
  reasoned): dropping them would let a save/load cycle visibly flip NPC
  attitudes, which is worse corruption than storing transition state. Tested:
  held stance survives round-trip and still holds on the next nudge.
- Orphan policy: obsolete memory kinds drop on load (they have no gate that
  can read them); everything else loads verbatim. NPC renames get a rename
  table only when the first rename happens — not prematurely.
- Seeds: exactly-once via synchronous booking in the reaction (obligations'
  transition() precedent); applier confirms. Journal duplicates of SeedFired
  are thereby impossible, verified by multi-step single-command advances.
- Scar reassessment (measured, not assumed): 400 transfers + 30 obligations +
  400 steps + 52 scars → 210KB save, scars 8.5KB (~4%), journal capped at 500.
  Verdict: current caps suffice; revisit only if long-running worlds show scar
  counts in the thousands (~164 bytes each). No new cap imposed.
- run-tests gains the tests/save stage. Inspector prints summaries (counts,
  versions, clock), never judgments; --full is explicit and local-only.
