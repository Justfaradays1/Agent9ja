# Decision — M009 world simulation scope (2026-10-09)

Founder-authorized M009 only. Contract: places/routines/intent/travel/
offscreen/shared-resources + transformer-fault → chatter → levy thread.
Compound + two nearby places. No coordinates/pathfinding/3D.

## Deliberate reductions and deviations (with reasons)

- **No hard-commitment intent level** (arch priority #1: shifts/meetings):
  no shift/meeting objects exist in the sim; nothing to key on. Deferred
  until a commitment model exists. Levels 2–5 implemented.
- **No seeded idle flavour:** arch permits RNG for idle flavour only. M009
  uses a deterministic idle (home) — one less nondeterminism surface to
  defend; flavour variation is an M010 tuning question with players.
- **No `content/people/npcs.json`:** no runtime consumer reads it (persons
  register via command; routine links journal through `set_routine`). Dead
  content is worse than none. Routines live in `content/people/routines.json`.
- **Emergency intent = fault-place only:** arch's "threads that name this
  person" needs a thread-assignee model that does not exist. Fault at your
  place → `dealing_with_fault` activity. Thread-named overrides deferred.
- **Levy money design (caretaker brokerage, P12):** `pay_levy` moves real
  kobo payer → collector via `MoneyMoved` (economy ledger stays consistent;
  no fake kitty account). The pot lives in the collector's wallet; the
  world store keeps the levy ledger (members/paid/due). Collector self-share
  emits no `MoneyMoved` (net-zero would fake pot money) but keeps the
  receipt — the pot-holder's hands already hold it. Ghost liability for a
  collector who spends the pot is future gameplay, noted, not built.
- **Funded target = repair price, not per-head × members:** setup rejects
  underfunded levies (`per_head × members < repair_cost`) so doomed levies
  fail loud at opening, not mid-sim. Surplus converts to integer generator
  fuel-minutes (kobo and minutes stay integer per M003 discipline).
- **Levy thread terminal states:** funded closes early via `ThreadClosed`
  (clean); failed closes at due_t where story expiry may win the race
  deterministically (story reacts first — boot order frozen by replay
  proofs). `ThreadClosed` backstop + `LevyClosed` carrying resolution make
  both paths safe; an expired-unfunded levy reads honestly as expired.
- **Ghost tags are collector → ghost, one per ghost:** O(members), not
  O(pairs × ghosts) — event-budget discipline. `open_levy` requires
  collector↔member relationships to exist (resolve check), because the
  `RelationshipTagged` applier throws on unknown pairs by design. The
  collector is exempt from ghost liability (organising labour is their
  share) and can never be their own ghost.
- **One fault + one levy at a time:** bounded state, matches one-compound
  scope. History capped at 5 closed levies.
- **Travel replace rule:** a new move while travelling restarts from the
  original `from` place. Edge case, deterministic, tested, documented.
- **Travel holds until arrival:** phase/obligation/fault evaluations never
  yank in-transit persons (arrival resumes routine when it lands on the
  block). Tested: explicit moves survive same-phase advances.
- **Exactly-once booking marks (story-seed precedent):** one multi-step
  command queues many StepAdvanced events before any emission applies, so
  edge triggers (arrivals, init, phase changes, fuel exhaustion, levy
  deadline) mark synchronously in reactions or every later step duplicates
  them — found by test (71 duplicate phase batches in a 2-day run), fixed
  the same way story seeds do it. Marks are transient (scrubbed on apply)
  except lastPhase/initialized, which are genuine persisted state.
- **Step-accurate time discipline (timing audit):** the live clock is fully
  advanced during resolve, so `q.time()` inside a multi-step command returns
  the FINAL step — routines/light evaluated against it fire hours early.
  World reactions use per-step `ev.data.minutes`/`ev.data.phase`, with
  `ev.data.crossed` as the boundary trigger (obligations/story already use
  `ev.data.minutes`; the `phase` field predates M009, so no journal-shape
  change). Accepted limitation, bounded and documented: single-shot
  reactions (obligation/fault/levy triggers) evaluate at command-end time —
  skew bounded by advance chunk size. M010 clients should advance in small
  increments for time-sensitive play.
- **Notifications gain a levy section** via the existing composed-query
  pattern (same as obligations/threads/requests) — the levy must reach the
  player to complete hear → judge → choose. No new coupling shape.

## Migration plan (authorization §4)

New `world` store ⇒ `SNAPSHOT_VERSION` 2 → 3, `migrateV2toV3` injecting
`emptyWorldState()` (owned by sim/world) when absent.
`CONTENT_VERSION` stays 1 (M007/M008 precedent: content additions don't
bump it). The v1 pre-M008 fixture now exercises the full v1→v2→v3 chain in
one load; a v2-shape test (current snapshot minus world store — exactly
what every 029a6a8-era save looks like) covers the second path.
