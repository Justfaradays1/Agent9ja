# Decision — M003 locked semantics (2026-10-08)

No architecture change. These close ambiguities the arch left open, using the
smallest semantics that satisfy the milestone. All are tested.

- Money is integer kobo; floats/strings/zero/negative rejected. No division
  exists in M003, so no remainder rule is needed yet — any future split logic
  (M004+) must define floor + remainder-to-first and test it.
- Settlement is atomic by construction (synchronous applier, validate-first);
  MoneyMoved + ObligationSettled/ObligationFulfilled always co-occur.
- Partial payments keep current status with truthful history entries; only a
  zero remainder emits ObligationFulfilled (arch event vocabulary preserved).
- Overpay refused; past-due creation refused; third-party payer refused
  (`payer_must_be_debtor` — revisit only with an explicit use case).
- Renegotiation requires `creditor_accept: true` (journaled attestation);
  old record terminal with full history; successor links back; consensual
  zeroing allowed, silent forgiveness impossible.
- Reactions receive frozen query views (`ctx.q`) so consequence mapping can
  check-before-emit (skip pairs with no relationship — never auto-create).
  Frozen views cannot mutate; verified by existing freeze tests.
- Favour derivation stays 0: M004 verbs will consume this ledger. Wiring it
  now would couple relationships to money semantics prematurely.
- Due scan is O(obligations) per StepAdvanced, sorted by (due_t, id);
  measured: 20 obligations × 7 days well under budget.
- Defaults locked: opening 0, grace 0, witnesses ≤8, query caps (200/50).
